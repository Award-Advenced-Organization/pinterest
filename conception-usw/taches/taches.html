USW · United State of World · Groupe 4

Tâches à accomplir

Version du 22 octobre 2026. Tout le travail du code, du socle à la mise en ligne, découpé en tâches à répartir entre les membres. Les détails techniques sont dans conception-usw/analyse/ARCHITECTURE.md, les écrans (E00 à E38) dans la maquette, sur la branche USW.

Lire une tâche

  • Code : T pour le groupe, B pour le backend Laravel, M pour l'application Flutter. Le chiffre des dizaines est le lot.
  • Taille : S, environ une demi-journée (1 point) ; M, un à deux jours (2 points) ; L, trois à cinq jours (4 points).
  • Après : les tâches à finir avant de la commencer.
  • Fini quand : ce qu'il faut montrer pour la déclarer terminée.
  • Membre : à remplir à la répartition.

Règles pour tous

  • On avance lot par lot, comme dans le TP : chaque tâche est testée avant la suivante.
  • Une tâche backend suit toujours le même ordre : migration, modèle, factory, Form Request, service ou action, contrôleur, ressource JSON, Policy, route, tests.
  • Une tâche mobile peut commencer avant sa tâche backend, avec des données simulées au format de l'API (section 8 d'ARCHITECTURE.md), puis se brancher sur la vraie API.
  • Une branche par tâche, partie de USW ; une demande de fusion relue par un autre membre ; tests au vert avant de fusionner.
  • PHP 8.5.12 au minimum sur chaque poste ; aucun secret (.env, clés) dans le dépôt.

Pour équilibrer la charge, il vaut mieux qu'un membre ait le backend et le mobile d'une même fonction (par exemple B13 et M11) : il connaît les deux côtés de l'échange.
